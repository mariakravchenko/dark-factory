<objective>
The phase's headline capability: one command answers every question OBS-01 asks.
`dark-factory status <run-id>` grows from eleven scalar fields into the full
report — run header, every role attempt with its worker and attempt number, the
artifacts, the questions and the human answers, the quality-gate command results,
the errors, the PR information, and the state-transition history — rendered with
`rich`, with `--json` carrying identical content.

Purpose: this is the command the core value names. "If the orchestrator cannot
explain where a run is, it cannot reliably resume it" is a claim about this
output. It is built last in the phase because every piece it composes — the
events reader, the non-events read-model sibling, the renderer, the git-committed
read — was proven on its own first.

Output: `RunReport` and its section DTOs, `read_run_detail`, `read_quality_gate`,
`render_run_report`, the expanded `status` command, and the updated CLI contract
tests.

> For any run, Dark Factory can say exactly where it is and retell everything that
> happened to it — the observability half of the durability thesis.
</objective>
