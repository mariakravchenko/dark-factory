<objective>
Close the two independent test-only defects G-10-1's diagnosis surfaced alongside the
gate-exhaustion root cause. Neither is a production bug; both are assertions pointed at
the wrong thing.

1. `tests/db/test_manual_check_loop04_adjacency.py` asserts the adjacency reason lands on
   the `RUN_FAILED` payload. Production deliberately does not put it there --
   `_EXHAUSTION_REASON_TO_COUNTER` maps only the two exhaustion reasons and runner.py's
   own comment states verbatim that an adjacency failure "simply misses and the payload
   stays `{"role": node.name}`". The reason IS persisted, on the `ROLE_FAILED` event's
   `error` field and on `role_executions.error`. The test reads the wrong event. The file
   is also the untracked throwaway STATE.md flags as a Blocker: it is the ONLY behavioural
   evidence LOOP-04's adjacency case was ever proven, and a `git clean` would silently
   destroy it.

2. `tests/integration/test_redaction_interactions.py`'s structural guard does a blanket
   `redact(` token search over the whole 1825-line `runner.py`. Phase 10 legitimately
   added two `redact(` call sites, both on the GitHub path, both scrubbing a `GitHubError`
   string -- one before it enters `PublishResult.error` (GIT-03), one before it enters the
   `QUESTION_CREATED` payload's `clarification_comment_error` key (GIT-05). Neither is
   human-interaction text. The contract the test's own docstring describes -- question and
   answer are scrubbed only inside `_write_human_interaction` -- is intact; the assertion
   is over-broad by construction.

Purpose: turn one throwaway into durable LOOP-04 evidence, and replace a stale token ban
with a guard that states the real SEC-01 contract and can prove it is not vacuous.

Output: a committed `tests/db/test_loop04_adjacency.py`, and a narrowed,
self-falsifying redaction guard.
</objective>
