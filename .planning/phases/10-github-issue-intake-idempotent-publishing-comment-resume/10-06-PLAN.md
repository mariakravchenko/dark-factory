<objective>
Turn plan 10-01's GitHub edge into a durable publish path. A terminal-role PASS verdict plus a
PASS quality gate now collects the final diff, commits, pushes and opens exactly one pull
request whose number, URL and commit SHA are persisted in the same transaction that completes
the run — and `dark-factory run github:152` works end to end for the first time.

Purpose: this is wave 2 of the phase's tracer slice, and the plan that proves the architecture
end-to-end. It also lays every persisted identifier the later plans check before acting:
`runs.published_commit_sha` (D-06) and the two `human_interactions` comment-id columns (D-05)
all land here in one Alembic revision, so no later plan needs a second migration. And it adds
the `github_client_factory` injection seam in `runner.py` that plans 10-02 and 10-03 reuse.

Output: `migrations/versions/0006_github_publishing_columns.py`, three new `EventType` members
(D-07), `Run.published_commit_sha` plus the two `HumanInteraction` comment-id columns (D-05,
D-06), `PublishFieldsWrite` and `apply_transition`'s new keyword, four new `RunState` fields,
`src/dark_factory/orchestrator/publish.py` (new), the publish step and the client-factory seam
wired into the existing terminal-role block, and db-tier proofs against a real PostgreSQL 17.
