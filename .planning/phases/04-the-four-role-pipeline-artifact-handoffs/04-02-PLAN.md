## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → orchestrator | The `spec:` locator is an operator-supplied filesystem path, given at the same trust level as the `text:` body the operator already types. |
| filesystem → orchestrator | The spec file's bytes become `NormalizedTask.body` and are persisted to `runs.normalized_task`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-07 | Information Disclosure | `input/loaders.py::_load_spec` | low | accept | A `spec:` locator can name any path the invoking operator can already read; the operator is the process owner, so this grants no capability they lack. Confining `spec:` to the repository root would break the legitimate "spec file lives outside the checkout" case. Accepted deliberately, not overlooked. |
| T-04-08 | Information Disclosure | `persistence/mutations.py::create_run` | medium | mitigate | A spec file may contain a credential. The existing `scrub_known_values` call on `normalized_task` inside `create_run` (D-18) already scrubs exact known secret values on the way into Neon, and `redact()` covers the `RUN_CREATED` payload. No new write path is introduced — `_load_spec` returns the same `NormalizedTask` type `_load_text` does and reaches Neon through the same single mutation path. |
| T-04-09 | Denial of Service | `input/loaders.py::_load_spec` | low | accept | An enormous spec file would be read into memory and persisted. `tests/db/test_schema_shape.py` already proves a 100 KB body round-trips, and the file is operator-supplied rather than attacker-supplied (same posture as `text:`). A cap would be arbitrary and is not introduced; revisit if Phase 10's GitHub intake makes the body third-party-controlled. |
| T-04-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs no package; `pyproject.toml` is not modified. `04-RESEARCH.md` § "Package Legitimacy Audit" records the phase as not applicable, so no legitimacy checkpoint is triggered. |
</threat_model>
