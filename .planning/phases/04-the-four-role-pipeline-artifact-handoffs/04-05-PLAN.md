Today `_synthesize_artifact_content` takes only `filename` and `_default_script` reads only `role`/`run_id`/`outputs` from the context — `inputs`, where `build_role_context` already deposits upstream artifact content, is never read. That missing parameter is the whole root cause; fix the data path, not the individual placeholder strings.

Add three module-level constants: an origin criterion-id tuple used only when a role received no id-bearing input at all (the BA case — this replaces BOTH existing hardcoded ids and becomes the single place an id originates); a compiled full-line regular expression that matches the Markdown criterion-carrier line described below and captures a single non-whitespace token as the id; and a cap on how many criterion ids one synthesis call will use.

Add a role-agnostic extraction helper that takes the context's `inputs` (read defensively through `getattr`, matching the existing `_default_script` idiom so a bare `None` or a test double degrades cleanly) and returns an ordered, de-duplicated tuple of criterion ids. For each input, read its `content` attribute defensively and skip anything that is not a string, then try two strategies in order and stop at the first that yields ids for that input: (1) structural — `AcceptanceCriteriaDocument.model_validate_json`, taking the criterion `id` values, with `pydantic.ValidationError` caught and treated as "this input is not an acceptance-criteria document" (pydantic v2 reports malformed JSON as a `ValidationError` too, so one except clause covers both non-JSON and wrong-shape inputs); (2) textual — the carrier-line regular expression over the raw content, which is how a Markdown input such as `design.md` carries ids forward. Dispatch is on the content's shape only. Never branch on `context.role`, never map a filename to a role, and never read anything off the filesystem here — D-08 keeps the worker role-agnostic and CTX-02 keeps this code out of the source tree.

Apply two safety filters to every candidate id before it is accepted, then truncate the accepted list to the cap: the id must be a single whitespace-free token and must not exceed a 64-character length limit. This bounds what upstream artifact content can inject into a downstream artifact (threats T-04-19 and T-04-21 below) — only short extracted tokens are ever copied forward, never an input's body.

When extraction yields nothing, return the origin-id constant. That is what makes the BA role the id origin without a second literal anywhere else.

- Any filename with no D-10 model (every `.md` output) — keep the existing heading and generic placeholder opening, then append one carrier line per id in D-07's own accepted style: a list-item line reading `Criterion <id> met`. Emit exactly the shape the carrier regular expression matches, so a Markdown artifact round-trips its ids to the next role. Keep the content non-task-aware: task-derived prose is Phase 7's scope per D-07.

Keep the change inside this one source file — no change to `domain/artifacts.py`, `context/builder.py`, the role YAMLs, or `.dark-factory.yaml` is required, and none should be made.
