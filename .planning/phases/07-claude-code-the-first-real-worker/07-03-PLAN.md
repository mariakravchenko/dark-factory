## Phase Goal

> **Goal (verbatim from ROADMAP.md):** A real agent runtime performs a role end to end,
> including pause and resume, while the orchestrator remains unable to tell which runtime
> it is talking to.
>
> **MVP note:** see 07-01-PLAN.md — the ROADMAP Goal line is not in user-story form and no
> story is invented here.

<objective>
Make the pause/resume half of the phase real: a role running through the actual `claude`
CLI can pause for a human decision and be resumed through the CLI's own session id — and
prove the orchestrator cannot tell that adapter apart from `FakeWorker`.

Purpose: SC2 says a paused run resumes through the adapter's native session id *and* a
worker declaring `native_resume=false` resumes by context reconstruction, with the
orchestrator issuing the identical call in both cases. Both branches live inside
`ClaudeCodeWorker.resume()` — the contract suite reaches the native branch when
`previous.worker_session_id` is set and the reconstruction branch when it is `None`, so one
adapter exercises both halves of HITL-04/HITL-05. Appending `ClaudeCodeWorker` to
`WORKER_FACTORIES` is what makes SC3/QUAL-02 true.

Output: `NEEDS_INPUT` marker parsing, a real `resume()`, accurate `capabilities()`, and a
contract suite that runs against both adapters with no live binary and no live credential.

Locked decisions implemented by this plan:
- D-01: clarifying-question signal — the role prompt instructs the agent to end its turn with
  a line-initial `NEEDS_INPUT:` marker followed by the question; the adapter parses that marker
  out of the CLI's own `result` text (present → `NEEDS_INPUT` with the extracted question,
  absent → `COMPLETED`/`FAILED` as usual). Adapter-only parsing, no new CLI feature dependency. (Task 1)
- D-03: timeout policy — `resume()` shares the single `Settings.worker_timeout_seconds` value
  with `execute()`; no second timeout knob is introduced. (Task 2)
</objective>
