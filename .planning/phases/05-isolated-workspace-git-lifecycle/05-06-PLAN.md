<objective>
Close G-05-2: author the missing CR-02 regression test. CR-02 changed `revert_paths` so that a
single escaping path can no longer abort the revert of every other violation queued behind it
— the containment check moved inside a per-path `try`/`except` that collects escapes and raises
once after the loop. That fix currently rests entirely on code review and manual reasoning,
with zero executed coverage at any test tier.

The coverage never needed a database. `src/dark_factory/git/scope.py` states in its own module
docstring that it performs no database access anywhere, and `revert_paths(worktree, paths)`
takes a plain path and only shells out to git. The gap exists because the module's coverage was
partitioned "pure functions to the unit tier, everything else to the full-pipeline integration
tier", leaving no obvious DB-free home — and because the test was then deferred on the
explicitly stated but incorrect premise that it needed the same database the integration tier
needs. A DB-free unit-tier home was already idiomatic here: `test_git_lifecycle.py`,
`test_git_diff.py` and `test_git_worktree.py` all drive real git against a `tmp_path`
repository. Full investigation: `.planning/debug/cr02-revert-ordering-test-gap.md`.

This is a **test-only** plan. No production code changes.

Purpose: make the CR-02 fix falsifiable. A pre-CR-02 implementation, which propagated the
first escape immediately, must fail the escape-first test in this suite.
Output: `tests/unit/test_write_scope_revert.py`, registered as a ROLE-05 / SC4 proof.
</objective>

    already-sorted list; none of them constructs a run, takes a database fixture, or goes
    through the orchestrator.

    1. **Escape sorted first** (the CR-02 regression proper). Pass the escaping symlink ahead of
       both in-repository violations. Assert the call raises `WriteScopeViolation`, and that
       *after* the raise: `src/app.py` holds its original committed content again and is no
       longer staged, and `src/new.py` is absent from disk and absent from the git index. This
       is the test that fails against the pre-CR-02 implementation, where the first escape
       propagated immediately and left both later violations in place. Say so in the test's
       docstring, naming CR-02, so nobody later prunes it as redundant with the escape-last
       case.
    2. **The escape itself is never acted upon.** In the same scenario, assert the symlink is
       still a symlink in the repository and that the file it points at still holds its
       original content. The containment check rejects, it never clamps and never deletes: an
       authorization control that reached outside the worktree to "clean up" would be a worse
       outcome than the violation it was correcting.
    3. **Exactly one raise, naming every escape.** Assert the raised exception is a single
       `WriteScopeViolation` whose message contains the escaping path's name. Use
       `pytest.raises` and inspect the message text.
    4. **Escape sorted last.** Same violation set, escape at the end. Assert the identical
       revert outcome as case 1 plus the raise. Together with case 1 this pins the property
       that matters: the revert outcome does not depend on where the escape sits in the list.
    5. **Escape only.** A list containing nothing but the escaping path. Assert it raises and
       that neither `src/` file is disturbed — with nothing revertible in the list, the
       function must still fail loudly rather than return quietly.
    6. **Multiple escapes.** Two escaping symlinks plus one in-repository violation. Assert the
       in-repository violation is reverted, and that a single raised exception names both
       escaping paths — the fix collects escapes and raises once, it does not raise on the
       first one it meets.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker → worktree filesystem | A role's writes cross into the repository checkout; `write_scope` is the authorization control over that crossing. `revert_paths` is the enforcement action, and this plan is what makes its escape handling falsifiable |
| worktree → everything outside it | A worker-created symlink can point outside the checkout. The containment check is the boundary; this plan proves the enforcement action never crosses it |
| test harness → developer filesystem | The suite creates real symlinks and runs `git clean` for real; its blast radius must stay inside `tmp_path` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-G2-01 | Elevation of privilege | `revert_paths` escape handling | high | mitigate | Task 1 case 1 proves an escape cannot suppress the revert of other violations — previously a single escaping symlink could have left real out-of-scope writes on disk while the role still failed, which is the worst of both outcomes |
| T-05-G2-02 | Tampering | `_resolve_in_worktree` containment check | critical | mitigate | Task 1 case 2 proves the escaping path is rejected and never deleted, restored or cleaned; the enforcement action provably does not reach outside the worktree root |
| T-05-G2-03 | Tampering | test harness `git clean` blast radius | medium | mitigate | Every repository and every escape target is created under the per-test temporary directory; the escape symlink points at a file the test itself created under that directory, never at a real path on the host |
| T-05-G2-04 | Repudiation | CR-02 fix provenance | high | mitigate | Task 3 maps the new proof under ROLE-05 and SC4 and records it in the validation map, so the Critical review finding and its executed proof are linked and the file cannot silently disappear from the gate |
| T-05-G2-05 | Information disclosure | new unit suite | low | accept | The suite reads and writes only fixture content it created; it holds no credential, takes no settings object, and by construction cannot reach `DATABASE_URL` since it opens no database connection |
