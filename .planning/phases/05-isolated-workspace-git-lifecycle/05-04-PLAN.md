<assumptions>
Flagged, unresolved probe items and adopted research assumptions carried into execution (surfaced, never silently dropped):

- **A-05-12 (RESEARCH Pitfall 1, adopted — it corrects the phase brief).** `write_scope` matching uses `fnmatch.fnmatchcase`, not the `pathlib` path-matching API. Research verified empirically on this project's Python floor that the `pathlib` matcher is right-anchored by path-component count and has no true recursive wildcard: it reports a match for `tests/fixtures/src/evil.py` against `src/**` (a false positive that would let an out-of-scope file pass) and no match for `src/sub/deep.py` against the same pattern (a false negative that would flag legitimate work). `fnmatch` has no path-separator concept, so its wildcard crosses `/` and its translation is fully left-anchored — which is exactly the semantics `write_scope` needs. `fnmatchcase` rather than the case-normalising variant, so behaviour does not vary with the host platform. D-12 names "fnmatch/pathlib globbing"; this plan takes the half that is correct.
- **A-05-13 (RESEARCH assumption A3, adopted with an explicit definition).** `fnmatch` has no syntax-error class — its translation accepts essentially any string — so "malformed pattern" has to be defined rather than detected. This plan defines it as: an empty or whitespace-only string, a pattern beginning with `/` (absolute), a pattern beginning with `./`, or a pattern containing a `..` path segment. Each of those is either meaningless against the relative paths git reports or an attempt to describe something outside the worktree. Anything else is accepted.
- **A-05-14 (the attempt's change set, decided here).** "The attempt's changes" (D-13) are the worktree's **uncommitted** changes at the moment of the check, enumerated as `git diff --name-only HEAD` plus `git ls-files --others --exclude-standard`, both with the `.dark-factory` exclusion. This is precise because plan 05-02's recovery pass made the tree clean at this role's entry and plan 05-03's artifact commit removed this role's own run-tree writes just before the check — so what remains is exactly this role's repository changes. The alternative, diffing the whole working branch against the base, would attribute every earlier role's work to the current one and is rejected.
- **A-05-15 (ignored files are out of scope for enforcement).** `--exclude-standard` omits gitignored files, so a role that produces build output or caches is not failed for them. ROLE-05 speaks of "a role's diff", and a gitignored file is by construction not in any diff.
- **A-05-16 (ROLE-05 concurrency probe, `backstop`).** Enforcement runs inside the single-owner lease, after the worker returns and before the transition commits, so two processes never enforce against one worktree. A crash part-way through reverting leaves a partially-reverted tree; the next entry's recovery pass commits whatever remains, so nothing is destroyed, and the attempt re-runs against a clean tree. That crash path is reasoned about but not directly exercised by a test in this phase.
- **A-05-03 (ART-04 edge probe, still UNRESOLVED).** Cross-machine transport remains Phase 11's concern; carried forward one final time so the phase closes with the assumption visible rather than dropped.

Work in this order; step 2's matcher is the one place research proved a plausible implementation is wrong, so write its tests first.

**1. `src/dark_factory/git/scope.py` — module frame.** New module in the register of `artifacts/paths.py` and `git/diff.py`: git-and-pure-function only, no database access, every function taking an explicit worktree path. Module docstring: `write_scope` is an authorization control (ROLE-05), so this module treats every path it is handed as untrusted and every pattern as a boundary definition; it states the D-14 polarity in one sentence and names the matcher choice with its reason.

**2. The matcher (D-12, D-14, A-05-12).** `is_out_of_scope(path: str, write_scope: Sequence[str]) -> bool` returns `not any(fnmatch.fnmatchcase(path, pattern) for pattern in write_scope)`. That is the whole body. Write the docstring to carry three facts a future reader needs and cannot infer:
  - Zero tolerance falls out of the empty list for free — a path matches none of zero patterns, so every path is a violation — and therefore **no early-return branch for the empty list may be added**. The intuitive `if not write_scope: return False` inverts D-14 and silently grants write access to the two read-only roles.
  - `fnmatch` is used rather than the `pathlib` path-matching API because the latter is right-anchored by path-component count with no true recursive wildcard on this project's Python floor, which produces both false positives against a decoy directory and false negatives against deep nesting; research verified both empirically.
  - `fnmatchcase` rather than the case-normalising variant, so behaviour is identical on a case-insensitive filesystem and a case-sensitive one.

**3. The attempt's change set (A-05-14).** `attempt_changed_paths(worktree: Path) -> list[str]` — the union of `run_git(["diff", "--name-only", "HEAD", "--", ".", ARTIFACT_EXCLUDE_PATHSPEC], cwd=worktree)` (tracked modifications, staged changes and deletions, relative to the last commit) and `run_git(["ls-files", "--others", "--exclude-standard", "--", ".", ARTIFACT_EXCLUDE_PATHSPEC], cwd=worktree)` (untracked, non-ignored files). Return the sorted, de-duplicated union of the non-empty stripped lines. Use these two invocations rather than parsing porcelain status output: the status format carries two-character prefixes and a rename arrow that must be stripped, and both of these emit bare paths. Docstring: the set is exactly this attempt's repository changes because the worktree was made clean at this role's entry by the recovery pass and this role's own run-tree writes were committed immediately before this check; and gitignored files are deliberately absent, because a gitignored file is by construction not part of any diff.

**4. The containment guard.** `_resolve_in_worktree(worktree: Path, relative_path: str) -> Path` — mirror `artifacts/paths.py::resolve_under_run_root` exactly: resolve the candidate, resolve the root, and raise `WriteScopeViolation` naming both when the candidate is not relative to the root. Reject, never clamp. Call it on every path before any revert or delete acts on it. In practice git will not emit an escaping path from a worktree Dark Factory itself created; the guard is there because this project treats every path crossing a trust boundary the same way, and `write_scope` is an authorization boundary.

**5. The revert (D-13, A revert that must branch — RESEARCH Pitfall 2).** `revert_paths(worktree: Path, paths: Sequence[str]) -> None`. For each path, first `_resolve_in_worktree`, then probe HEAD membership with `run_git(["cat-file", "-e", f"HEAD:{path}"], cwd=worktree, check=False)` and branch on the exit code:
  - **Present in HEAD** — `run_git(["restore", "--source=HEAD", "--staged", "--worktree", "--", path], cwd=worktree)`, which returns both the index and the working tree to the committed content.
  - **Absent from HEAD** — the role created this file, so there is nothing to restore to and the restore command fails outright with a pathspec error. Clear any index entry with `run_git(["rm", "--cached", "--force", "--quiet", "--", path], cwd=worktree, check=False)` and then remove the file itself with `run_git(["clean", "--force", "--", path], cwd=worktree)`.
  Docstring: branching on HEAD membership is mandatory, because a single-mechanism revert leaves every newly-created violating file on disk (and possibly staged) while appearing to succeed. Act on exactly the paths supplied and nothing else — never a whole-tree reset, never an untargeted clean, never a checkout of the current directory — because an enforcement mechanism that destroys the role's legitimate in-scope work is a worse outcome than the violation it was correcting.

**6. The enforcement entry point.** `enforce_write_scope(worktree: Path, *, write_scope: Sequence[str], role: str, attempt: int) -> None` — enumerate with `attempt_changed_paths`, collect **every** out-of-scope path (do not short-circuit on the first, so the error names the complete set), and when the collection is non-empty: revert them all, then raise `WriteScopeViolation` whose message names the role, the attempt, the configured patterns and the sorted violating paths. Revert before raising, so the caller cannot accept a failure that left the offending change on disk. Return `None` when the collection is empty.

**7. Pattern validation (A-05-13).** `validate_write_scope_patterns(patterns: Sequence[str], *, source: str) -> None` in the same module, raising `ValueError` naming `source` and the offending pattern when a pattern is empty or whitespace-only, begins with `/`, begins with `./`, or contains a `..` segment when split on `/`. Docstring: `fnmatch` has no syntax-error class — its translation accepts nearly any string — so "malformed" has to be *defined*; these four cases are the ones that are either meaningless against the relative paths git reports or an attempt to describe something outside the worktree. Call it from `load_effective_config` in `src/dark_factory/config/loader.py` while resolving each role, wrapping the `ValueError` into `ConfigError` with the role file path, in the exact register of the existing instructions-path guard — so a bad pattern is rejected before `create_run`, and the CLI's existing mapping turns it into exit 2 with nothing persisted. Export the new names from `src/dark_factory/git/__init__.py`'s `__all__`.

**8. Ship real scopes on the two write-capable roles (D-12, D-14).** Set `permissions.write_scope` to `["src/**"]` in `.dark-factory/roles/DEVELOPMENT.yaml` and to `["tests/**"]` in `.dark-factory/roles/QA.yaml`, replacing the empty placeholders, and rewrite the comment above each to say what it now means rather than that it is deferred. Leave `.dark-factory/roles/BA.yaml` and `.dark-factory/roles/ARCHITECTURE.yaml` at `[]` and add one line to each saying the empty list is the **intended** zero-tolerance value for a read-only role (D-14), not a placeholder awaiting a value — otherwise the next reader will "fix" it. Mirror the same four values in `tests/conftest.py`'s `_write_config_tree` so the test tree and the shipped tree agree, and check whether any existing test in `tests/unit/test_repo_config_schema.py` asserts an empty `write_scope` for DEVELOPMENT or QA; update it to the new value rather than weakening the new one.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker → repository source | A role's worker has filesystem write access to the whole worktree. `write_scope` is the post-hoc authorization control over what it was permitted to change; it is enforced by the orchestrator, never by the worker. |
| git output → orchestrator | Paths reported by `git diff --name-only` and `git ls-files` become arguments to destructive commands (restore, index removal, clean). They are treated as untrusted input and contained before use. |
| repo config → authorization decision | `permissions.write_scope` in a role YAML is repo-controlled text that defines a security boundary. It is `yaml.safe_load`-parsed, `extra="forbid"`-validated, shape-validated at load, and snapshotted per run so an edit cannot change an in-flight run's boundary. |
| persisted snapshot → enforcement | The patterns come from the run's own snapshot, not from a live file read, so the boundary a run is judged against is the one that existed when it started. |
