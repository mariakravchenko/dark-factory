<objective>
**As a** Dark Factory operator, **I want to** be able to hand a colleague nothing but a run id and a clone of the repository and have them see every artifact that run produced, **so that** "the run's state is durable" covers the files the roles wrote and not only the rows in Neon — and so that none of that machinery ever reaches the pull request I publish.

This plan resolves ROADMAP Open Decision 1. It commits each completed role's artifact content onto the run's working branch, keeps that content out of the base branch and out of the PR-bound diff, makes `collect_diff` real, and closes the run's worktree lifecycle at `COMPLETED`. It is ROADMAP Phase 5 SC2 end to end.

Purpose: make artifact content travel with the branch, and make the diff that will become a pull request contain the work and nothing but the work.
Output: `dark_factory.git.diff`, the per-role artifact commit, a real `collect_diff`, the `COMPLETED` cleanup, and the test-suite migration from reading artifacts off disk to reading them off the branch.
</objective>

Flagged, unresolved probe items and adopted research assumptions carried into execution (surfaced, never silently dropped):

- **A-05-08 (a correction to RESEARCH Pattern 3, verified against a real repository at plan time).** RESEARCH gives the artifact commit as `git add -A -- .dark-factory/runs/<run_id>/`. That command **fails with exit 1** in this repository, because `.gitignore` excludes `.dark-factory/runs/` and `git add` refuses an explicitly-named ignored path without `-f` (`hint: Use -f if you really want to add them.`). The correct invocation is `git add -f -- <path>`, and the commit must be pathspec-limited (`git commit -m <msg> -- <path>`) so that source changes a worker happened to stage are not swept into an artifact commit. Both forms were executed against a real repository while planning; the fix is not speculative.
- **A-05-09 (Claude's discretion, exercised).** `collect_diff` writes its output to `<run_root>/verification/diff.patch`. `ensure_run_tree` has created a `verification/` directory since Phase 4 with no writer; this is its first real consumer. The action has no return channel — its registered callable type returns nothing — so a file in the run tree is the only durable way for it to hand a result to Phase 9's quality gate and Phase 10's publisher. The file is written by an `after:` hook, which runs *before* that role's artifact commit, so it is carried by the same commit and is excluded from the PR diff by the same pathspec.
- **A-05-10 (an honest limitation of D-10's literal form, stated rather than worked around).** `git diff <base>...<working>` is a commit-range diff: at the moment a role's `after:` hook runs, that role's own edits are still uncommitted, so they are not yet in it. They join on the next role's entry, when the WIP recovery from plan 05-02 commits them, and the terminal role's are joined by this plan's `COMPLETED` cleanup pass. The PR-bound diff is therefore complete by the time a run finishes, which is when Phases 9 and 10 consume it. D-10's literal form is kept; the timing is documented in `collect_diff`'s docstring rather than papered over by inventing a second diff semantics.
- **A-05-03 (ART-04 edge probe, `unclassified`, still UNRESOLVED and carried forward).** The probe's ART-04 row is the cross-machine transport question. This plan proves the half that is in scope — a fresh clone of the working branch has the content — and leaves actual cross-machine orchestration (SSH, rsync, a CI handoff) to Phase 11, per `05-CONTEXT.md` `<domain>`. Recorded as an open assumption, not a silent drop.
- **A-05-07 (carried from 05-02, resolved here).** RESEARCH Pitfall 5 notes the terminal role has no "next entry" to recover its trailing edits. The `COMPLETED` cleanup in Task 2 runs one final `wip_commit_if_dirty` pass before removing the worktree, adopting RESEARCH assumption A4. - **A-05-11 (RESEARCH Open Question 3, adopted).** Worktree removal happens **after** the terminal `apply_transition` has committed. A lingering worktree after a recorded `COMPLETED` is a recoverable disk-space gap; a removed worktree whose database write then failed would be a real loss window.
- **A-05-12 (D-16, a gap found and closed after the checker's initial pass — see `05-CONTEXT.md` D-16 for the full mechanics).** D-09's artifact commit alone does not survive an ephemeral CI runner being destroyed, because nothing was pushed to `origin` until Phase 10 — contradicting D-09/D-11's own "durable... by being committed to the working branch" framing for exactly the audience (ordinary ephemeral CI execution) the project's Core Value statement names. `push_working_branch` closes this by pushing right after the artifact commit, authenticated via `GIT_ASKPASS` (never argv, never a URL), retried a bounded number of times via `tenacity` (already a project dependency; CLAUDE.md names `git push` explicitly as a tenacity use case), and folded into the same `except GitError` → `ROLE_FAILED` path `commit_run_artifacts` already uses — no new event type.

  <behavior>
    - After a role completes, exactly one new commit exists on the run's working branch whose subject begins with `chore(dark-factory):` and names the role and the run id, and whose changed-file list is entirely under `.dark-factory/runs/<run_id>/`.
    - That commit exists even though `.gitignore` lists `.dark-factory/runs/` — `git ls-files` on the working branch names the artifact files, while the same paths remain untracked on the base branch.
    - A four-role run produces four such commits, one per role, in role order, each containing only that role's newly-written files.
    - Calling the commit step a second time for the same role with no new content produces no commit and raises nothing: the branch tip is unchanged.
    - Calling the commit step for a run whose artifact directory does not exist returns without invoking `git add`.
    - A git failure that is not the empty-change-set case propagates as `GitCommandError` and fails the role, rather than being swallowed.
    - A role that ends `FAILED` (for example on a schema violation) produces no artifact commit.
