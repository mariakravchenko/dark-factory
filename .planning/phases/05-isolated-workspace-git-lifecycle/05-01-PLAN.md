<objective>
**As a** Dark Factory operator, **I want to** have every run own an explicit working branch and a real isolated git worktree that all of its roles execute inside, **so that** a run's repository work is isolated from my main checkout and from every other run, and the branch it will eventually publish exists under a name that is recorded in Neon before any git command runs.

This plan is the phase tracer. It wires **one** thin path through every layer the phase touches: `create_run` persists the branch names → `load_run_state` reads them back → `_run_current_role` creates (or reuses) the sibling worktree → the run tree and the role context resolve inside it → the role's worker executes → the run completes. No WIP recovery, no artifact commit, no write-scope enforcement yet — those are plans 02, 03 and 04 expanding out from this proven slice.

Purpose: prove the worktree spine end-to-end, on production-quality code, before three more plans build on top of it.
Output: the `dark_factory.git` package (error hierarchy, subprocess client, worktree lifecycle), the two populated `runs` branch columns, the runner's worktree wiring, a real-git test fixture, and the migrated test suite.
</objective>

**1. The `dark_factory.git` package skeleton and its error hierarchy.** Create `src/dark_factory/git/__init__.py` with a module docstring in the register of `src/dark_factory/artifacts/__init__.py`: state that this package is the **only** place in `dark_factory` that invokes the `git` binary (GIT-02), that nothing in it opens a `Session` or constructs a lifecycle ORM row (WR-01), and that every function takes explicit paths and returns plain values or raises a typed error. Declare the hierarchy: `GitError(RuntimeError)` as the base; `GitCommandError(GitError)` carrying `args: tuple[str, ...]`, `returncode: int` and `stderr: str` as attributes plus a message that names the subcommand, the exit code and the first line of stderr; `DetachedHeadError(GitError)`; `WorktreePathError(GitError)`; `WriteScopeViolation(GitError)`. `DetachedHeadError` and `WriteScopeViolation` are declared now and raised by plans 05-02 and 05-04 — declaring the whole hierarchy in one place keeps the package's error surface legible. Re-export from `__init__` the five error classes plus `run_git`, `git_env`, `working_branch_name`, `worktree_path`, `ensure_worktree`, `remove_worktree`, and list them in `__all__`.

**2. `src/dark_factory/git/client.py` — the one subprocess wrapper.** Mirror `tests/support/subprocess_runner.py`'s discipline exactly. Define `GIT_ENV_ALLOWLIST: tuple[str, ...] = ("PATH", "HOME", "LANG", "LC_ALL", "LC_CTYPE", "TZ", "TMPDIR", "TEMP", "TMP", "SSL_CERT_FILE", "SSL_CERT_DIR", "SYSTEMROOT")` — the names git genuinely needs to find its binary, its cert bundle and a temp directory, and nothing else. Define `GIT_IDENTITY_ENV: dict[str, str]` pinning `GIT_AUTHOR_NAME` / `GIT_COMMITTER_NAME` to `"Dark Factory"`, `GIT_AUTHOR_EMAIL` / `GIT_COMMITTER_EMAIL` to `"dark-factory@invalid"`, `GIT_CONFIG_NOSYSTEM` to `"1"`, and `GIT_TERMINAL_PROMPT` to `"0"` — the identity vars make every commit this project writes deterministic and attributable regardless of the operator's personal git config, and the prompt var guarantees a git subprocess can never block waiting on a terminal. Define `git_env() -> dict[str, str]` returning `{name: os.environ[name] for name in GIT_ENV_ALLOWLIST if name in os.environ} | GIT_IDENTITY_ENV` — build the mapping by allowlist comprehension; the parent process environment is never duplicated wholesale, because that is precisely how a database URL or a GitHub token would reach a subprocess that has no business seeing one. Define `run_git(args: Sequence[str], *, cwd: Path, check: bool = True, timeout: int = 120) -> subprocess.CompletedProcess[str]` calling `subprocess.run(["git", *args], cwd=str(cwd), env=git_env(), capture_output=True, text=True, timeout=timeout, check=False)` — an argument list, never an interpolated command string — and raising `GitCommandError` when `check` is true and `returncode` is non-zero. Return the completed process otherwise so callers can inspect an expected non-zero exit (`git symbolic-ref -q HEAD` exiting 1, `git diff --cached --quiet` exiting 1) with `check=False`. Add a module-level note that `git` is invoked by name from `PATH` and never from a repo-controlled string.

**3. `src/dark_factory/git/worktree.py` — branch naming and idempotent worktree lifecycle.** Follow `artifacts/paths.py`'s "compute the deterministic path, check existence, only act if missing" idiom.
  - `WORKTREE_PARENT_DIRNAME = "dark-factory-runs"`.
  - `working_branch_name(run_id: UUID) -> str` returning `f"dark-factory/run-{run_id}"` (D-01). A pure string function with no I/O, so `persistence/mutations.py` can call it inside its transaction.
  - `worktree_path(repo_root: Path, run_id: UUID) -> Path` returning `repo_root.resolve().parent / WORKTREE_PARENT_DIRNAME / str(run_id)` (D-02). Docstring: a sibling of the main checkout, because git refuses to nest a worktree inside the tree it is a worktree of.
  - `ensure_worktree(repo_root: Path, run_id: UUID, *, base_branch: str | None, working_branch: str | None) -> Path`. Raise `WorktreePathError` naming the run id when `working_branch` is `None` (a run created before this phase, or a caller that skipped the persisted column) — never re-derive the name, because the persisted value is the identifier every later git effect is guarded by. Compute `target = worktree_path(repo_root, run_id)`. **Idempotency check first (RESEARCH Pitfall 4):** when `target.is_dir()` and `(target / ".git").exists()`, return `target` immediately without invoking git — a worktree's `.git` is a *file* pointing at `<main>/.git/worktrees/<name>/`, so its presence is a sufficient, cheap marker. Otherwise raise `WorktreePathError` when `base_branch` is `None`, then create the branch and the worktree in the single verified one-shot invocation `run_git(["worktree", "add", "-b", working_branch, str(target), base_branch], cwd=repo_root)`; missing parent directories in `target` are created by git itself. A non-existent `base_branch` surfaces as `GitCommandError` from `run_git` with git's own `fatal: invalid reference: <name>` in `stderr`; let it propagate. Return `target`.
  - `remove_worktree(repo_root: Path, run_id: UUID, *, force: bool = False) -> bool`. Compute the target, return `False` when it does not exist, otherwise `run_git(["worktree", "remove", *(["--force"] if force else []), str(target)], cwd=repo_root)` and return `True`. Declared here now; plan 05-03 wires it to the `COMPLETED` transition (D-04).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| orchestrator → `git` subprocess | The first non-worker subprocess Dark Factory spawns. Its argument list carries a run-derived branch name and filesystem paths; its environment is the credential boundary. |
| repo config → orchestrator | `.dark-factory.yaml`'s `repository.base_branch` is repo-controlled text that becomes a `git` argument. Already `yaml.safe_load`-parsed and `extra="forbid"`-validated in Phase 3. |
| Neon → orchestrator | `runs.working_branch` / `runs.base_branch` are read back and passed to `git`; they are written only by `create_run`, never by a worker or a repo file. |
| filesystem → orchestrator | The worktree directory and its `.git` marker are the existence signal `ensure_worktree` branches on; a hostile symlink at the target path would redirect every later git effect. |
