<objective>
Add the actual G-11-3 deliverable: the runtime analogue of plan 11-06's import-time guard. 11-06
proved that every module in the `dark_factory` package *imports* in a database-free process. That
guard could not have caught G-11-3 by construction — it sweeps package imports and never imports
anything under `tests/`, so it cannot observe a settings read that happens during test *execution*
on a conditionally-taken branch. This plan adds the missing half.

Purpose: this defect class has now reached CI twice. Both times it was invisible locally for the
same reason — the repository's git-ignored environment file silently satisfies the two required
settings fields on every run from the repository root — and both times the cost was a full
push-wait-read-CI cycle plus a UAT cycle. A guard that reproduces CI's own condition locally turns
that into a local failure. Plan 11-08's declared inventory catches a *new production* read
statically in milliseconds; this catches a *new test* reaching an existing read, empirically.

Output: one new unit-tier module running three child processes — the full sanitized tier, the
live-suite collection adversary, and a positive control — plus the re-run of UAT test 1 that
confirms the gap is actually closed on a real GitHub-hosted runner.
</objective>

environment allowlist, working directory outside the repository, a positive control — applied to
execution rather than import.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| parent pytest process -> child probe processes | The guard spawns three child processes and hands each an environment. That environment is a credential boundary in exactly the sense CLAUDE.md defines, and it is also the thing under test. |
| `tmp_path` -> the child's `PATH` and import path | Test 2 writes executable files into a temporary directory and prepends it to a child's `PATH`; Test 3 writes a Python test file a child collects and runs. Both are code the harness places and a child resolves. |
| `.github/workflows/ci.yml` -> the guard's own assertion | The guard derives what it proves from a workflow file, so the workflow is an input to a test rather than only an output of the repository. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-39 | Information Disclosure | the environment handed to the three child processes | high | mitigate | A harness built with a wholesale copy of the parent environment would hand this repository's real environment-file-loaded database URL, GitHub token and worker API key to spawned probe processes — and would *also* make Tests 1 and 2 pass vacuously, which is the worse of the two harms because it would hide a live defect while appearing to guard it. Task 1 mandates an explicit named allowlist tuple with the two database variables absent rather than blanked, mirroring the idiom `tests/support/subprocess_runner.py` documents, plus the Test 3 positive control that fails the moment sanitization stops working. |
| T-11-40 | Denial of Service | the child process spawned by Test 1 | high | mitigate | A child that collects this module spawns its own grandchild tier, recursing without termination and consuming the machine — the worst possible failure mode for a test added to a tier developers run constantly. Task 1 mandates exclusion by this file's own resolved absolute path (never by name match, marker or environment sentinel, each of which a rename or stray variable defeats) and a generous but explicit subprocess timeout that surfaces as a named failure. The measured bound is 275s locally against 37s on the hosted runner. |
| T-11-41 | Tampering | the stub worker binaries Test 2 writes onto a child's `PATH` | medium | mitigate | Placing executables named after real agent CLIs at the front of a `PATH` is, in any other context, a path-hijacking attack. It is confined here by construction: the directory lives under pytest's `tmp_path`, the prepended `PATH` exists only in one child process's environment dictionary and never in the parent's, the stubs are never invoked (only resolved), and the child runs collect-only so no test body can reach a worker spawn. Task 1 also derives the names from the live-runtime registry rather than hardcoding them, so the set cannot silently diverge from the binaries the probe actually looks for. |
| T-11-42 | Repudiation | the marker expression the guard asserts against | medium | mitigate | A hardcoded selector would let `ci.yml`'s step change while the guard kept proving a property about a command nobody runs — a green test that means nothing, which is how this gap class survived two phases.
