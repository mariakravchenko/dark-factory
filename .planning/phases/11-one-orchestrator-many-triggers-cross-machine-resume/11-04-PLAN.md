<objective>
Make QUAL-01's coverage claim true in the only sense that counts: the `FakeWorker` orchestration
suite actually runs in CI, on every push and pull request, with no AI call and no worker
credential — and add the guard that fails the build the day that stops being so.

Purpose: 11-RESEARCH.md's scenario-gap audit found no content gap. Every one of the eight scenarios
QUAL-01 names already has a passing `tests/db/` module, written across Phases 4 through 10. The
gap is that this ~177-test tier has never been selected by `.github/workflows/ci.yml`, whose
comment currently says the hosted runner "provides neither a Postgres 17 instance nor agent-CLI
credentials". Half of that is now wrong: GitHub-hosted `ubuntu-latest` ships a running Docker
daemon, so `tests/conftest.py`'s existing testcontainers rung provisions PostgreSQL 17 with no
`services:` block and no new secret (D-05). The other half is still right, and the corrected
comment has to say which half is which — otherwise the next reader deletes the `integration`
exclusion too and CI starts failing on missing `ANTHROPIC_API_KEY`.

Purpose, second half: turning the tier on is a one-line change that a later edit could silently
undo. The guard in Task 2 binds QUAL-01's eight scenario nouns to named modules that must exist
and must carry the `db` marker, and asserts the workflow still selects that marker — so "covered"
stays a statement about an executed command rather than about a file.

Output: a `ci.yml` that runs `unit`, `contract` and `db`, with a budget sized for the new work and
a `<human-check>` to calibrate it against a real run; and a unit-tier guard that keeps the claim
honest.

Deliberately NOT in this plan: the dispatch code path and its tests (plans **11-01**, **11-02**);
the cross-machine proof this tier will now execute (plan **11-03**); the deployer documentation
(plan **11-05**). No `tests/db/` module is rewritten by this plan — 11-RESEARCH.md's audit found
nothing to rewrite, and rewriting a passing suite to prove it passes would be work that adds risk
and removes nothing.

The phase's single artifact index lives in `11-01-PLAN.md` under "Artifacts this phase produces".

shares no file with 11-01 and would run correctly before it. It waits because 11-01 is the phase's
tracer slice and a tracer is verified before expansion.
</objective>
