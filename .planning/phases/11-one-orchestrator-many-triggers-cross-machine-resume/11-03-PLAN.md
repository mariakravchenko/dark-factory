<objective>
Prove the phase's headline claim for real: a run that pauses on one machine finishes on another
through Neon alone. D-06 makes the shape explicit — two `dark-factory` CLI subprocesses inside one
job, both pointed at the same PostgreSQL, with every scrap of process-local and on-disk state
deleted in between — and this plan builds exactly that, plus the structural guard that says there
is only one orchestration implementation for either process to run.

Purpose: SC1 and SC2 are the two success criteria this phase exists for, and neither has an
automated proof today. The closest existing test, `tests/integration/test_fresh_process_resume.py`,
proves the *crash* case (SC2 of Phase 2) and is marked `integration`, a tier `ci.yml` deliberately
never runs. This plan proves the *pause-and-hand-off* case, the one a real local→CI boundary
takes, and — per D-05/D-06 — marks it `db` so it actually runs in CI.

Output: one new db-tier module with the two-process proof and its single-process control, and one
new unit-tier structural guard pinning TRIG-01.

Deliberately NOT in this plan: the dispatch code path and its degraded branches (plans **11-01**
and **11-02**); turning on the `db` marker tier in `.github/workflows/ci.yml` (plan **11-04**,
which is what makes this plan's test actually execute in CI); the deployer-facing `resume.yml`
reference (plan **11-05**).

**Marker deviation, deliberate and documented (11-RESEARCH.md Pitfall 1).** Every existing test in
this repository that spawns `dark-factory` as a real OS subprocess lives under `tests/integration/`
and carries `pytestmark = pytest.mark.integration`. This plan's new test spawns two and is
nonetheless placed under `tests/db/` and marked `pytest.mark.db`. The reason is that the two
markers' real differentiator here is *what the test needs*, not *what it does*: `integration` is
excluded from CI because some of its tests need live agent-CLI credentials the hosted runner does
not have, and this test needs only PostgreSQL and `FakeWorker`. 11-CONTEXT.md D-05 is explicit —
"the `db`-tier test suite (and the cross-machine proof below) runs in `ci.yml`". Marking it
`integration` would mean it silently never runs in CI while this plan's checklist says "done",
which is precisely the failure mode plan 11-04's prohibition names. The deviation must be recorded
in the new module's docstring citing D-05/D-06, not left as an unexplained inconsistency.

**Assumption (this plan's own): the lease is released cleanly by process A.** `dark-factory run`
exits a `WAITING_HUMAN` pause through `typer.Exit(code=0)`, which unwinds normally, so
`run_lease.__exit__` runs and the lease is released — unlike `test_fresh_process_resume.py`'s
crash case, which uses `os._exit` and therefore needs the `force_lease_expiry` fixture. Task 1 is
written on that assumption. If process B returns `LeaseNotAcquired`, the assumption is wrong:
apply the existing `force_lease_expiry` fixture (as the crash proof does) and record the finding
in the SUMMARY, because "a clean pause leaks its lease" would be a real defect worth a follow-up,
not a test-authoring detail.

**Test 1 — `test_a_run_paused_by_one_process_is_finished_by_another_with_nothing_carried_over`.**
Five phases, in order, with assertions between each:

1. **Pause.** `spawn(["run", "text:finish me somewhere else"], child_env(pg_url, fake_script=_PAUSE_SCRIPT), cwd=config_root)`.

   clean exit — `cli.py`'s `_CLEAN_FINALS` rule). Assert `"TimeoutExpired" not in (stdout + stderr)`.
   Read the run id with `run_id_from_stdout(p1.stdout)`.
2. **The committed pause.** Assert status `WAITING_HUMAN`, exactly one `role_executions` row,
   exactly one `human_interactions` row in its pending state, and capture that role row's `id` and
   `attempt` for the later comparison.
3. **Erase every local trace.** Compute `worktree_path(config_root, run_id)` and
   `run_root(config_root, run_id)`, `shutil.rmtree` both with `ignore_errors=True`, then assert
   both paths are absent with `.exists()` checks. Add a comment naming what this simulates: a CI
   runner's fresh checkout has the repository's committed `.dark-factory/` configuration but has
   never seen this run's worktree or its untracked artifact output. Deleting them is the strongest
   honest form of "no local state carried over" that a single filesystem permits.
4. **Resume from a genuinely separate process.** Build `resume_env = child_env(pg_url)` and assert
   explicitly that neither `"DARK_FACTORY_FAKE_SCRIPT"` nor `"DARK_FACTORY_CRASH_AFTER"` is a key
   in it — mirroring the analog's own explicit negative assertion, which is what makes "the second
   process is not the first one in disguise" a checked fact rather than a claim. Capture the
   `runs` count. Then `spawn(["resume", str(run_id), "--answer", "<the answer>"], resume_env, cwd=config_root)`
