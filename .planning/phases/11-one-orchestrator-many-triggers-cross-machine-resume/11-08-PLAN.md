<objective>
Close the production half of G-11-3. `run_publish_step` already receives its settings-derived
`known_secrets` as a parameter and uses it at two places, but reaches back to the process-global
`get_settings()` for the push token inside the same function. That single line accounts for 6 of
the 12 CI failures: a unit test whose git spy reports a commit SHA with `published_commit_sha`
unset takes that branch, constructs a bare `Settings()`, and dies on the two required database
fields that CI deliberately does not configure.

Purpose: this is the only one of G-11-3's five fix items where the correct change improves
production design rather than only a test's setup. Threading the token removes a hidden global
read from a function whose contract already says settings arrive as arguments, and makes six
tests pass with zero mocking. The companion inventory guard then makes the whole class of
"hidden process-global settings read" visible in the ~4 minute unit tier instead of in a pushed
CI run — the defect has now escaped to CI twice (G-11-1, G-11-3).

Output: a `run_publish_step` with no settings import at all, its one caller wired from the
`Settings` object it already holds, every test call site updated, one new assertion proving the
token actually arrives, and one new unit-tier inventory guard over `src/dark_factory/`.
</objective>
