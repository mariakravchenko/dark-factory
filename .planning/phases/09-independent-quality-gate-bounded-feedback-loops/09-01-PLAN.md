<objective>
Make Dark Factory's own quality gate real: once the pipeline's terminal role finishes an
attempt whose `verdict.json` computes PASS, the orchestrator itself runs the repository's
configured `quality_gate.commands` inside the run's worktree, folds a PASS/FAIL decision
from exit codes alone, writes `verification/quality_gate.json`, and refuses to let the run
reach `COMPLETED` when any command failed.

Purpose: this closes the gap 09-RESEARCH.md calls Critical Mechanics Gap 1 — today nothing
in `runner.py` reads `verdict.json`'s content, and a run with a FAILing verdict reaches
`RunStatus.COMPLETED` unconditionally. This plan is where GATE-01..GATE-04 become real and
where the ROADMAP invariant "verdicts from exit codes and machine JSON, never prose" first
has teeth.

Output: `src/dark_factory/orchestrator/quality_gate.py` (new), three new `EventType`
members, the verdict-read + gate block wired into `_run_current_role`, and unit + db proofs.

Interim behaviour established here, upgraded in plan 09-02: a FAIL verdict or a FAIL gate
transitions the run to `RunStatus.FAILED` via the existing `Signal.ROLE_FAILED` shape.
Plan 09-02 replaces that terminal outcome with the bounded `Signal.ROLE_BOUNCED` loop at
the same signal-override seam — a behavioural upgrade at an existing seam, not an
architectural change.

Create `src/dark_factory/orchestrator/quality_gate.py` and wire it into `_run_current_role`.

**The new module** exports `GateCommandResult`, `QualityGateResult`, `run_quality_gate` and
`write_quality_gate_result` via `__all__`.

`GateCommandResult` is a pydantic v2 model with `model_config = ConfigDict(frozen=True,
extra="forbid")` and exactly five fields, named to mirror `ShellResult` plus the originating
string: `command: str`, `exit_code: int | None`, `stdout: str`, `stderr: str`,
`timed_out: bool`. Do not add a sixth field — D-11 pins this shape.

`QualityGateResult` is a frozen `extra="forbid"` model with one declared field,
`commands: list[GateCommandResult]`, and a `status` exposed as a pydantic v2
`@computed_field` over a `@property` returning `VerdictStatus` (imported from
`dark_factory.domain.status`; reuse it rather than minting a second PASS/FAIL enum). The
property returns `VerdictStatus.PASS` when every entry satisfies `exit_code == 0` and
`timed_out is False`, else `VerdictStatus.FAIL`. Because it is a computed field it is
serialized by `model_dump_json()` but has no constructor argument — that is what makes
"never hand-set" structural rather than a convention (the same discipline
`Verdict.computed_status` uses). A zero-length `commands` list therefore folds to PASS with
no empty-list branch, exactly as `Verdict.computed_status`'s `all(...)` does. Note for the
executor: pydantic serializes computed fields after declared fields, so the emitted JSON key
order is `commands` then `status`. That is correct — do NOT introduce a settable `status`
field to reorder the keys.

`run_quality_gate(*, commands: Sequence[str], cwd: Path, timeout: int, known_secrets:
Mapping[str, str]) -> QualityGateResult` iterates `commands` in order and, for each, converts
the configured string to an argv list with `shlex.split` before calling
`dark_factory.tools.env.shell_execute(command=<argv>, cwd=cwd, role="quality_gate",
timeout=timeout)`. `shell_execute` is called directly as a plain function — no `ToolRegistry`
involvement, which its own docstring confirms is correct for orchestrator-invoked calls.
`role="quality_gate"` is deliberately not one of the six `RunStatus` role values, so the
`tests/unit/test_no_role_name_literal.py` guard stays green. Never spawn a child process from
this module by any other route: `shell_execute` is what threads `build_worker_env`'s
credential allowlist and the `start_new_session=True` + process-group kill on timeout
(T-09-01, T-09-02). The loop never breaks early — every configured command runs even after an
earlier non-zero exit (D-09).

Each captured `stdout` / `stderr` is post-processed in this order before the
`GateCommandResult` is built: first `dark_factory.events.redaction.redact(text,
known_secrets=known_secrets)` (patterns enabled — the default — so `github_pat_` / `ghp_` /
postgres-URL / bearer shapes are caught as well as exact known values), then a tail-preserving
cap at a module constant `_MAX_CAPTURED_OUTPUT_BYTES = 16 * 1024`. When the encoded text is
over the cap, keep the trailing bytes and prepend one marker line naming the number of dropped
bytes so the truncation is explicit in the persisted text, never silent. The cap exists because
`verification/quality_gate.json` is read back through `read_artifact_text`, whose
`_MAX_ARTIFACT_BYTES` is 262144 — an uncapped `pytest` failure dump would make the file
unreadable and crash a later role attempt.

`write_quality_gate_result(run_dir: Path, result: QualityGateResult) -> str` writes the file at
the relative path `verification/quality_gate.json`, resolving it with
`dark_factory.artifacts.paths.resolve_under_run_root`, creating the parent directory with
`mkdir(parents=True, exist_ok=True)` and writing `result.model_dump_json()` with
`encoding="utf-8"` — the exact shape `collect_diff` already uses for its own `verification/`
write. Return the relative path string so the caller can put it in an event payload.
