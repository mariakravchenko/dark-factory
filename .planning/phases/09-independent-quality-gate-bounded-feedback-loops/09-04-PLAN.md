<objective>
Close verification gap CR-01: `enforce_write_scope` — this project's ROLE-05 authorization
control — is skipped entirely whenever the terminal role's attempt resolves to
`Signal.ROLE_BOUNCED` instead of `Signal.ROLE_COMPLETED`, because the guard was written in
Phase 5 before `ROLE_BOUNCED` existed and Phase 9 never widened it. A bounced attempt's
out-of-scope write is therefore never detected and never reverted; it survives uncaught into
the next role's WIP-recovery commit, indistinguishable in the audit trail from that role's own
legitimate work.

Purpose: restore the ROLE-05 boundary across the new control-flow edge Phase 9 introduced, and
make sure a scope violation correctly downgrades a would-be bounce to a genuine failure instead
of leaving a stale counter increment and bounce reason behind.

Output: the widened guard and its side-effect-clearing violation handler in `runner.py`, a
unit-tier AST structural regression guard that runs in any environment, and a db-tier
behavioural regression test that drives a real run.

`behavior_unverified_items` in `09-VERIFICATION.md` are *not* gaps — they are existing,
collection-clean db-tier tests that were never executed because this sandbox has no reachable
PostgreSQL. No task here re-implements or re-tests them; the recommended re-run is recorded as
a Manual-Only Verification below.
