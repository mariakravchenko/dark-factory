<objective>
Make `HermesWorker` a real, working `CodingWorker` adapter registered under the name
`hermes`, completing the three-real-runtime set and emptying `WorkerRegistry` of
placeholders.

Purpose: this plan broadens the 08-01 tracer sideways to the second new runtime. Hermes
differs from Copilot in three ways that matter and are handled explicitly here: it has no
dedicated credential and reuses `Settings.anthropic_api_key`; it keeps its config and
session state in a home-directory directory that must be isolated per role; and
`NATIVE_TOOL_CONTRACT` records that it exposes no per-tool native restriction flag at
all, which forces a spawn-admission decision this plan surfaces rather than settles
silently.

Output: `src/dark_factory/workers/hermes.py`, the final registry registration, a
reusable fake-`hermes`-on-PATH test helper, a unit suite proving all of the above with no
live `hermes` binary, and the shared contract suite running over all four workers.

Locked decisions implemented by this plan:
- D-02: no live `hermes` binary exists here, so the adapter is implemented against
  documented invocation patterns and proven against a faked executable on `PATH`. (Tasks 1-3)
- D-03: `NEEDS_INPUT` signal reuse — this adapter imports the one shared marker, protocol
  text and extraction regex from `workers/cli_runtime.py`; no second literal is created. (Task 1)
- D-04: `hermes` becomes a real registered factory, which is the precondition for the
  `QA` role's reassignment to it in 08-04. (Task 1)

Claude's-discretion items resolved here, with the research finding each rests on:
- No `Settings.hermes_api_key` is added. Hermes is multi-provider and documents
  `ANTHROPIC_API_KEY` among its own recognised provider keys, and no NousResearch-branded
  single credential exists (08-RESEARCH.md Finding 1). Inventing a field name the CLI does
  not read would make every Hermes role fail with a misleading error.
</objective>

  <decision>
`src/dark_factory/tools/native.py` states, for all seven capabilities, that Hermes
"documents no per-tool native restriction flag" and that therefore **"the adapter must not
spawn Hermes for a role denied this grant at all — there is no flag to fall back to."**
`tests/unit/test_native_tool_contract.py::test_hermes_entries_are_honest_about_having_no_native_mechanism`
pins that prose.

Read literally, that rule admits Hermes only for a role holding **every** capability in the
contract. `.dark-factory/roles/QA.yaml` grants `repo.read, repo.search, repo.write_tests,
shell.execute, artifacts.read, artifacts.write` and deliberately withholds `repo.write` —
Phase 6 SC1's "QA can write tests but cannot publish" half. So the literal rule makes
`HermesWorker` refuse every QA attempt, and D-04's locked `QA` -> `hermes` assignment
(ROADMAP SC2's own literal example) can never complete.

This is a genuine conflict between a locked user decision and a published Phase-6 design
contract. It is surfaced rather than settled in the adapter, because every way out either
weakens a security contract or overrides a locked decision.
  </decision>
  <options>
    - **Option A (recommended): narrow the refusal rule to capabilities with no compensating control.**
      Amend each `NATIVE_TOOL_CONTRACT` entry's `absent_behaviour` so the Hermes clause
      distinguishes two cases: for `repo.write` and `repo.write_tests`, denial is
      compensated after the fact by `enforce_write_scope` (ROLE-05), which reverts and fails
      any changed path outside the role's configured `write_scope` — including the
      zero-tolerance empty scope — so the adapter may spawn and let that control hold the
      boundary; for `repo.read`, `repo.search`, `shell.execute`, `artifacts.read` and
      `artifacts.write`, no post-hoc control exists, so the refusal stands and the adapter
      must not spawn. `spawn_is_permitted()` implements exactly that split.
      Cost: a Phase-6 contract's prose and its guard test change. Benefit: the rule becomes
      true rather than absolute, D-04 is honoured, and QA's `write_scope: ["tests/**"]`
      does real work as the named compensating control.
    - **Option B: implement the literal rule and change the SC2 assignment.**
      `HermesWorker` refuses any role not holding all seven capabilities; `QA` is assigned to
      a different runtime and Hermes takes a fully-granted role instead. Cost: contradicts
      locked decision D-04 and ROADMAP SC2's own literal example — requires the user to
      re-open that decision.
    - **Option C: grant `repo.write` to the QA role.**
      Makes QA fully granted so the literal rule admits it. Cost: directly contradicts Phase 6
      SC1 ("QA can write tests and shell but cannot publish") and the deliberate 06-01 D-16
      decision to leave `repo.write` off QA. Not recommended.
  </options>
  <recommendation>
Option A. The contract's underlying principle — "an adapter that cannot enforce a
restriction natively must not claim that it can" — is preserved: the amended prose still
refuses to claim native enforcement, it just names the real, already-shipped control that

break a decision that was made deliberately and recorded.
  </recommendation>
