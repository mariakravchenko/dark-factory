<objective>
`context_prompt_sections` in `src/dark_factory/workers/cli_runtime.py` tells a role to
write its declared outputs under `artifacts/<ROLE>` -- the raw `RoleContext.artifacts_dir`
value, which is **run-root-relative**. But the agent's cwd is the *worktree*, and the
`--allowedTools` grant it is spawned with covers
`.dark-factory/runs/<run_id>/artifacts/<ROLE>/**`. A role that writes exactly where the
prompt tells it is therefore denied by the real `claude` CLI, and under
`--permission-mode dontAsk` it gets no prompt to learn from -- it must rediscover the
real path by trial and error against denials, and sometimes gives up instead.

Confirmed live against two real `app-int` CI runs (BA `Write` calls denied). Recorded as
an open concern twice already: STATE.md Blockers/Concerns `[Phase 10]` finding (1), and
`[Quick 261030-o5x]` follow-up (b), which notes the two bugs compound into a role with no
useful signal to self-correct from.

**The prompt is the component that is wrong, not the glob.** The grant's prefix is
required and correct, corroborated by five independent sites:
`native.py:245-260`'s `NATIVE_TOOL_CONTRACT` specifies the prefixed specifier verbatim;
`git/scope.py:171,202` uses `.dark-factory/runs/{run_id}/artifacts` and documents it
in-line as *"relative to the worktree"*; `collect_declared_artifacts`
(`cli_runtime.py:357-359`) resolves `artifacts_dir` against `root = run_root(work_dir,
run_id)`; `tools/registry.py`'s `_artifacts_read` does the same; and
`tests/unit/test_git_diff.py:76` asserts `.dark-factory/runs/{run_id}/artifacts/BA/output.json`
is what reaches the PR branch. Dropping the prefix from the glob would break artifact
collection, keep artifacts out of the PR, and move the write grant outside the run
sandbox into the target repo's own tree.

Purpose: make the prompt name the path the grant permits, so prompt, grant, collection,
and git pathspec are four spellings of one location.
Output: a one-site prompt fix, a coordinated fake-CLI update, a three-way agreement
regression test, and the STATE.md resolution record.
</objective>
