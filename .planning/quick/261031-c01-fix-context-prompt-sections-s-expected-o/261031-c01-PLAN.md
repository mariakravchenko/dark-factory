<objective>
`context_prompt_sections` in `src/dark_factory/workers/cli_runtime.py` tells a role only
*where* to write each declared output and what to *name* it:

    ## Expected outputs
    - requirements.md (write under .dark-factory/runs/<id>/artifacts/BA)
    - acceptance_criteria.json (write under .dark-factory/runs/<id>/artifacts/BA)

For a Markdown document that is complete information. For a **machine artifact** -- one of
the five filenames `artifacts/validation.py`'s `MACHINE_ARTIFACT_MODELS` registry
schema-validates under the D-09 gate -- it is not. The role is handed a filename and
nothing else, then has its output rejected by `model_validate` for not matching a pydantic
shape it was never shown. A role running against an external target repo cannot read
Dark Factory's own `domain/artifacts.py` to find out. Observed live during Phase 10 UAT
(real Claude Code workers against `mariakravchenko/app-new`): the BA invented a plausible
JSON shape and produced **31 validation errors**. That is Phase 10 UAT finding (2), still
open after `261030-op0` deliberately scoped it out.

The fix: for each declared filename that is a key of that registry, call the real model
class's `model_json_schema()` and render it into the same `## Expected outputs` section.
Filenames with no registry entry keep their bare bullet and get no schema -- they carry no
schema by design (ART-02).

Two design decisions this plan locks, both load-bearing:

**1. One registry, read from the domain layer.** `MACHINE_ARTIFACT_MODELS` currently lives
in `artifacts/validation.py`, which imports `persistence.mutations`, which imports
`dark_factory.git.worktree` (`mutations.py:56`) and SQLAlchemy. Importing it from
`cli_runtime.py` would drag that whole chain into every worker adapter's import graph and
transitively break the GIT-02 boundary `cli_runtime`'s own docstring asserts -- the AST
guard in `tests/unit/test_git_ownership_boundary.py` is per-file and would not catch it,
which makes it worse, not better. So the dict **moves** to `domain/artifacts.py` (pydantic
+ `domain.status` only -- the layer that already owns all five models, and the layer
`workers/fake.py` already imports for exactly this purpose) and `artifacts/validation.py`
re-exports it. Still exactly one dict literal in `src/`; the established import path
`from dark_factory.artifacts.validation import MACHINE_ARTIFACT_MODELS` keeps working, so
`tests/unit/test_artifact_models.py` needs no edit.

**2. The bullet line is byte-frozen; schemas go below it.**
`tests/support/fake_cli.py`'s `OUTPUT_BULLET_RE` is `^- (\S+) \(write under (.+)\)$` with
`re.MULTILINE`. That `$` anchors to end-of-line, so appending even ` -- must match:` to the
bullet would silently stop the shared fake CLI from parsing ANY declared output, breaking
every `declared_outputs=True` test and the orchestrator integration suite. The bullet list
is therefore emitted exactly as it is today, with one `### {filename} schema` block per
machine artifact appended after the complete list, inside the same section.

**Measured prompt cost** (actual `json.dumps(..., indent=2)` lengths, all five models):
`acceptance_criteria.json` 1495 chars, `constraints.json` 1002, `implementation_summary.json`
1243, `test_report.json` 1533, `verdict.json` 3708. No role declares more than two; the real
worst case is QA (`test_report.json` + `verdict.json`) at 5,241 chars ~ 1,310 tokens, and BA
is ~375 tokens. Schema `description` values (generated from the model docstrings) are kept
rather than stripped: they are the *only* place the cross-field invariants live -- `Verdict`'s
declared-`status`-must-equal-`computed_status` fold, the `min_length=1` reasons, the
no-duplicate-id rules -- and those are precisely what an agent inventing a shape gets wrong.
Stripping them would also mean writing and testing a recursive stripper for a few hundred
tokens of savings. Not worth it.

Purpose: close Phase 10 UAT finding (2) -- a role is told the exact shape its output must
match, by the same object that will judge it.
Output: a schema-carrying `## Expected outputs` section, one registry, two regression tests,
STATE.md updated.
</objective>
