# Quick Task 261031-c01: Fix context_prompt_sections's Expected-outputs section to carry real pydantic schemas Summary

Each machine-artifact output declared by a role now carries its real `model_json_schema()`, rendered from the same registry the D-09 gate validates against — closing Phase 10 UAT finding (2), where a real Claude Code worker invented a plausible-but-wrong JSON shape and produced 31 validation errors.

## What Was Built

`context_prompt_sections` in `src/dark_factory/workers/cli_runtime.py`'s `## Expected outputs` section previously told a role only a filename and a write destination. For any declared filename that is a key of `MACHINE_ARTIFACT_MODELS` (`acceptance_criteria.json`, `constraints.json`, `implementation_summary.json`, `test_report.json`, `verdict.json`), the section now also renders a `### {filename} schema` sub-block containing a one-line instruction (`OUTPUT_SCHEMA_PREAMBLE`) plus the model's real `model_json_schema()` as a fenced `json` code block. Markdown-only outputs (`requirements.md`, `design.md`) keep their bare bullet and get no schema, by design (ART-02).

To make that possible without widening `cli_runtime.py`'s import graph (GIT-02), `MACHINE_ARTIFACT_MODELS` was relocated from `src/dark_factory/artifacts/validation.py` to `src/dark_factory/domain/artifacts.py` — the pure-pydantic domain layer that already owns all five models — and `validation.py` now re-exports the same dict object. The established import path `from dark_factory.artifacts.validation import MACHINE_ARTIFACT_MODELS` is unchanged, so `tests/unit/test_artifact_models.py` needed zero edits.

### Key implementation details

- `cli_runtime.py` imports `MACHINE_ARTIFACT_MODELS` from `dark_factory.domain.artifacts` (never from `dark_factory.artifacts.validation`), with an inline comment warning against "simplifying" that back — `validation.py`'s `persistence.mutations` import reaches `dark_factory.git.worktree`, and this module must never import `dark_factory.git`, even transitively.
- The bullet-list literal `f"- {filename} (write under {destination})"` is byte-for-byte unchanged; schema blocks are appended as a separate list joined with `"\n\n"` after the bullet block, inside the same `## Expected outputs` section string, so `tests/support/fake_cli.py`'s `OUTPUT_BULLET_RE` (`^- (\S+) \(write under (.+)\)$`, `MULTILINE`) still parses every declared filename.
- `OUTPUT_SCHEMA_PREAMBLE` names the three failure modes the pydantic models actually enforce: exact validation, every required field present, no fields outside the schema, every enum value spelled exactly as listed.
- `context_prompt_sections`'s docstring gained a new paragraph explaining why a machine artifact carries its schema, citing Phase 10 UAT and the shared-registry guarantee.
- Two new regression tests in `tests/unit/test_claude_code_worker.py`, placed immediately after `test_expected_outputs_prompt_path_is_identical_to_granted_write_glob`:
  - `test_machine_artifact_outputs_carry_their_real_pydantic_schema` — recomputes `model_json_schema()` on the registry's own model class at assert time (never a pasted literal) and asserts it appears verbatim in the prompt; asserts a Markdown output gets no schema block.
  - `test_output_bullets_remain_parseable_with_schemas_present` — asserts `OUTPUT_BULLET_RE.finditer` still returns every declared filename in order with schemas present, and that a Markdown-only context produces no fenced JSON.
