<design_decisions>

These were settled during planning by reading the real contract. Do not re-litigate them; implement them.

**DD-1 — Instruction prose is read from this repo at runtime, not copied into the script.**
The script resolves `Path(__file__).resolve().parents[1] / ".dark-factory" / "instructions"` and reads `ba.md`, `architecture.md`, `development.md`, `qa.md` from there. This satisfies "the same role-generic prose this repo already contains, not re-invented" *by construction* and makes drift impossible. If that directory or any of the four files is absent, the script exits non-zero naming the missing path — it never falls back to invented prose.

**DD-2 — A generated write-scope section is appended to each copied instruction file.**
This repo's `development.md` tells the Developer to "add or update tests", but the role YAML the script generates gives DEVELOPMENT `write_scope: ["src/**"]` — a test file written under `tests/` would be reverted and would fail the role. The copied prose therefore gets a short generated trailing section naming the role's *actual* write-scope patterns (and, for the two zero-tolerance roles, naming that any changed path at all is a violation). The prose is still this repo's, verbatim; the appended section is derived from the role config the same run just emitted, so prose and enforcement cannot disagree.

**DD-3 — Text templating, not `yaml.dump`.**
`.dark-factory.yaml` and the role YAMLs carry explanatory comments that `yaml.dump` would silently delete. Templates are module-level string constants in the script with `{{PLACEHOLDER}}` tokens substituted by plain `str.replace`. PyYAML is used only to *parse-check* what was written. No new dependency, no templating engine.

**DD-4 — The role YAML templates are modelled on `app-int`'s, not on this repo's own.**
This repo's `.dark-factory/roles/*.yaml` are heavily annotated with Dark-Factory phase history (`08-04 (ROADMAP SC2)`, `WR-01 (04-REVIEW)`, `Phase 6 (plan 06-01, D-16)`) and assign `worker: fake` / `copilot` / `hermes` for this project's own proof purposes. Those are wrong for a target repo. `app-int`'s versions are the clean generic form and are the template. (This is the opposite of DD-1 on purpose: the *instructions* are already generic here, the *role YAMLs* are not.)

**DD-5 — Worker credential env vars are derived from the assigned workers.**
Read from the shipped adapters: `claude-code` -> `ANTHROPIC_API_KEY`, `hermes` -> `ANTHROPIC_API_KEY` (`HERMES_CREDENTIAL_ENV_VAR`), `copilot` -> `COPILOT_GITHUB_TOKEN` (`COPILOT_CREDENTIAL_ENV_VAR`). The generated `.env.example` and the `env:` block of the generated `resume.yml` carry the *union* over the four assigned roles — never the full set, never a hardcoded `ANTHROPIC_API_KEY`.

**DD-6 — Accepted worker names are exactly `claude-code`, `copilot`, `hermes`.**
`fake` is registered in `default_registry` but is this project's own test worker; it is not offered by the scaffolder. An unrecognised `--worker-*` value exits non-zero naming the three legal values.

**DD-7 — Never clobber. Skip-unless-`--force`.**
Every target file that already exists is skipped with a warning line; `--force` overwrites. The script prints a per-file summary (`created` / `skipped (exists)` / `overwritten`) and exits 0 when it did useful work. Exit non-zero only on a genuine error (bad worker name, missing instruction source, unwritable target).

**DD-8 — Location and non-registration.**
The file is `scripts/scaffold_target_repo.py` (new top-level `scripts/` directory). It is NOT added to `[project.scripts]` in `pyproject.toml`, NOT imported by anything under `src/`, and adds no Typer subcommand. It is invoked as `uv run python scripts/scaffold_target_repo.py ...`.

</design_decisions>
