<objective>
**As a** Dark Factory operator, **I want to** trust that a retried role never sees a superseded attempt's work and that a malformed machine artifact stops the run instead of poisoning it, **so that** the pipeline's handoffs are safe to build the rest of the delivery lifecycle on.

This plan closes the phase's two remaining success criteria — SC4 (retry context isolation) and SC5 (schema violation fails the role; the transition after QA is decided by `verdict.json`, never by prose) — and installs the Phase 4 acceptance gate as a sibling of the Phase 1, 2 and 3 gates.

Purpose: turn the invariants the earlier plans built by construction into named, failing-if-broken proofs, and leave a gate that fails loudly if any of them silently disappears in a later refactor.
Output: two database proofs, the phase acceptance gate, and a filled-in `04-VALIDATION.md` per-requirement test map.
</objective>
