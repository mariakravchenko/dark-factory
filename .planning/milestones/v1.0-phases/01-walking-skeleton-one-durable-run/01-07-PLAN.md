<objective>
Prove the two claims the whole project rests on: that a brand-new process can pick up a run where a dead one left it, and that a crash between the sub-writes of a transition can never leave a half-written run.

**User story framing (MVP mode).** **As an** operator whose machine died halfway through a run, **I want to** type `dark-factory resume <run-id>` on a fresh process and have it finish correctly, **so that** I trust the factory with work that takes longer than one process's life.

These are success criteria SC2 and SC4, and they are the reason the architecture looks the way it does. Everything in Plans 04 through 06 was arranged so that these two tests can be written honestly rather than staged: `advance` reconstructs from columns every call, and `apply_transition` commits once. This plan adds the minimum test seam needed to kill a process at a chosen moment, and then holds the system to both claims.

Purpose: satisfy ORCH-06's crash-consistency half and STATE-08's reconstructable-from-persisted-data-alone claim, and success criteria SC2 and SC4.
Output: a killed-then-resumed run reaching the same terminal state across two processes, and a crash-injected transition proven to roll back completely and still be resumable.
</objective>
