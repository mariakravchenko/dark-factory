**Selected: `recommended` — A1 + B1 + C1.** Pre-decided by the human; not re-prompted. Implemented exactly:

- **A1 — UUID v4 primary keys.** `runs.id`, `role_executions.id`, `run_events.id` are `sa.Uuid()` columns with a client-side `uuid.uuid4` default; `role_executions.run_id`, `run_events.run_id` and `run_events.role_execution_id` are matching `uuid` foreign keys. A run id is safe to print on stdout line 1 and paste into `resume`.
- **B1 — `sa.Enum(RunStatus, native_enum=False, create_constraint=True, length=32, name="run_status")`.** `runs.status` is a `VARCHAR(32)` with a CHECK constraint (`run_status`) carrying **all ten** STATE-07 values from revision 0001. No native PostgreSQL `ENUM` type. Verified in the live database:
  `CHECK (((status)::text = ANY ((ARRAY['CREATED','BA','ARCHITECTURE','DEVELOPMENT','QA','VERIFYING','PUBLISHING','COMPLETED','WAITING_HUMAN','FAILED'])::text[])))`
- **C1 — `run_events.seq` = `sa.BigInteger` + `sa.Identity(always=False)`** → `GENERATED BY DEFAULT AS IDENTITY`. It is the ordering key (`ORDER BY seq`), never `created_at`. Composite index `ix_run_events_run_id_seq` on `(run_id, seq)`.
