<objective>
Define the contracts the tracer slice is wired from: the run-status enum, the signal vocabulary, the normalized task and worker-result models, the event catalog, and the `CodingWorker` port with its registry and `FakeWorker` implementation.

**User story framing (MVP mode).** **As a** developer building Dark Factory, **I want to** hand any agent runtime the same `CodingWorker` contract and receive the same `WorkerResult` shape back, **so that** the orchestrator can drive a role without ever knowing which runtime performed it.

This is the "define the contracts" step of interface-first ordering. It is deliberately the *only* plan in the phase that introduces new type definitions, so the tracer in Plan 05 and every expansion after it receive their contracts in the plan rather than by exploring the codebase. Everything here is pure Python with no database and no I/O, so its whole verification runs in the sub-second `unit` tier.

Purpose: satisfy STATE-07 (the ten-value status set), WORK-01 (one contract for all runtimes), WORK-03 (no worker-name branching), WORK-08 (one normalized result shape) and WORK-10 (a scripted fake with no external AI call).
Output: importable, fully typed, fully unit-tested domain and worker contracts.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Worker adapter → orchestrator | A `WorkerResult` is the only thing crossing back from a runtime the orchestrator does not control. In Phase 1 the "runtime" is in-process, but the boundary must already be validated as if it were not. |
| `DARK_FACTORY_FAKE_SCRIPT` environment variable → `FakeWorker` | Externally supplied JSON parsed into domain objects. |
