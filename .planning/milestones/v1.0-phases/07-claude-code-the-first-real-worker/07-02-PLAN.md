## Phase Goal

> **Goal (verbatim from ROADMAP.md):** A real agent runtime performs a role end to end,
> including pause and resume, while the orchestrator remains unable to tell which runtime
> it is talking to.
>
> **MVP note:** see 07-01-PLAN.md — the ROADMAP Goal line is not in user-story form and no
> story is invented here.

<objective>
Give this repository its first CI pipeline, and make the existing worker-name leak guard an
actual build gate.

Purpose: ROADMAP SC4 says "A CI check fails the build when a worker name appears outside the
adapter modules." `tests/unit/test_no_worker_name_leak.py` already exists and already passes
locally, but 07-RESEARCH.md confirmed there is **no `.github/workflows/` directory in this
repo at all** — so today there is no build for that guard to fail. A passing local pytest
file is not a CI check. This plan closes that gap, and adds a guard-on-the-guard so the
wiring cannot be quietly removed later.

Output: `.github/workflows/ci.yml` plus a unit test that structurally verifies it.
</objective>

Create `.github/workflows/ci.yml`. There is no analog to copy in this repository — 07-PATTERNS.md records this explicitly — so build it from standard GitHub Actions plus `uv` conventions.

Shape: `name: ci`; triggers `on.push.branches: ["**"]` and `on.pull_request`; one job `quality` on `runs-on: ubuntu-latest` with `timeout-minutes: 15`. Steps in order: `actions/checkout@v4`; `astral-sh/setup-uv@v6` with `enable-cache: true`; `uv python install 3.12`; `uv sync --all-extras --dev --frozen`; then four separate, individually-named run steps so a failure names itself in the Actions UI:

1. `Lint (ruff)` running `uv run ruff check .`
2. `Types (mypy)` running `uv run mypy src/dark_factory`
3. `Worker-name leak guard (QUAL-04)` running `uv run pytest -q tests/unit/test_no_worker_name_leak.py`
4. `Unit and contract tiers` running `uv run pytest -q -m "unit or contract"`

Step 3 is deliberately a separate, explicitly-pathed step even though step 4 would also pick the guard up via the `unit` marker: SC4 names this specific check, and a dedicated step makes the gate legible in the Actions UI and greppable by the Task 2 guard. Every step must be left at the default blocking behaviour — no step may be allowed to pass the job on a non-zero exit, and no step may pipe or `||` its way past a failure.

Exclude the `db` and `integration` markers. `tests/conftest.py`'s probe ladder needs a reachable PostgreSQL 17 (Docker, a local `initdb`, or `DARK_FACTORY_TEST_DATABASE_URL`) and the `integration` tier drives the CLI as a real subprocess; the hosted runner provides none of those and no agent-CLI credentials. Add a YAML comment above step 4 stating that exclusion and why, so a future reader does not assume the tiers were forgotten.

Add a `concurrency` block keyed on `${{ github.workflow }}-${{ github.ref }}` with `cancel-in-progress: true`, and a top-level `permissions: contents: read` so the workflow token is read-only — it never needs to write to the repo.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub-hosted runner -> repository contents | The workflow token can read repository contents; it must never be able to write, tag, or publish. |
| Pull-request author -> CI execution | A PR from a fork executes workflow definitions; the job must hold no secrets it does not need. |
