<objective>
Make artifact content readable for the runs an operator actually asks about —
the finished ones. `dark-factory artifacts <run>` lists the metadata Neon holds,
and `--show <artifact-id>` prints the file body read out of the run's working
branch via `git show`, because the worktree that once held it is gone.

Purpose: 12-RESEARCH.md found this by reading the source rather than assuming —
`_cleanup_run_worktree` removes the worktree on every COMPLETED transition
(D-04, Phase 5), so a `--show` implemented against a live path works perfectly in
a mid-pipeline smoke test and raises a file-not-found for every run that
succeeded. The test tier already proves the right mechanism; production has no
equivalent yet. This plan promotes it.

Output: `git/committed.py`, `ArtifactRow`, `read_artifact_rows`,
`read_artifact_target`, `render_artifacts_table`, the `artifacts` command.

Reading through git also makes the code path uniform — identical for a mid-flight run and a finished one — rather than branching on `run.status`, which would put a lifecycle decision inside a read.

Do not catch `GitCommandError` here. A missing path or an unknown branch is information the caller needs in order to produce a useful exit-2 message, and swallowing it into an empty string would make "the file is empty" and "the file does not exist" indistinguishable. Let it propagate as the `GitError` subclass it already is.

Add both names to the `dark_factory.git` package `__all__` alongside the existing exports, following however the package already re-exports `client` and `diff` symbols.

## Trust Boundaries

| CLI argv (`--show <id>`) → `git show <branch>:<path>` | An operator-supplied value selecting a file to read out of a git object database. |
