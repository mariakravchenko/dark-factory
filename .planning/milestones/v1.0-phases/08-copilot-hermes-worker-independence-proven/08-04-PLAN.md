<objective>
Prove WORK-09 and ROADMAP SC2 literally: reassign the shipped pipeline's roles across all
three real runtimes in configuration — Architect on Copilot, Developer on Claude Code, QA on
Hermes — and show that the run still completes with no change to workflow code.

Purpose: this is the phase's headline claim. Two new adapters are only interesting if a role
can be moved between runtimes by editing a YAML field, and the honest way to demonstrate that
is to move the *shipped* roles, not a throwaway copy, and to show that the run's terminal
state, role sequence and artifact set are identical to the same pipeline running entirely on
`FakeWorker`. That equality — same everything except the `worker:` lines — is what "no change
to workflow code" means in practice.

Purpose, second half: making that true requires the test-support fake CLIs to behave like real
agents in one specific respect — writing the declared output files their prompt asks for.
Task 1 and Task 2 build that, reusing `FakeWorker`'s own synthesis rather than inventing a
second copy of minimal schema-valid content.

Output: public artifact-synthesis helpers in `workers/fake.py`, a declared-outputs mode shared
by all three fake CLIs, the three reassigned role YAMLs, an updated zero-config pipeline test,
and `tests/integration/test_role_reassignment_sc2.py`.

Locked decisions implemented by this plan:
- D-04: the SC2 proof uses ROADMAP's own literal example — Architect on `copilot`, Developer on
  `claude-code`, QA on `hermes`, with `BA`'s worker at planning discretion and left on `fake`
  because it is not named in the roadmap's example and is not load-bearing for the independence
  proof. (Task 3)
- D-02: no live binary exists here, so the proof drives fake executables on `PATH`; the
  property under test is the configuration-to-runtime wiring, which is identical either way.
  (Tasks 2-3)

`.dark-factory/roles/DEVELOPMENT.yaml` currently reads `worker: fake`. Phase 7 built the
adapter and registered it but never reassigned the shipped role. Task 3 therefore edits three
role files, not two.
