<objective>
Make `CopilotWorker` a real, working `CodingWorker` adapter registered under the name
`copilot`, and factor the binary-agnostic half of `ClaudeCodeWorker` into one shared
CLI-adapter runtime module so the second and third adapters inherit it instead of
duplicating it.

Purpose: this is the tracer slice for Phase 8. After Task 1 a role configured with
`worker: copilot` genuinely spawns a second, different external agent runtime and comes
back with a normalized `WorkerResult`, instead of raising `NotImplementedError`. Tasks 2
and 3 harden that same single path: it must never raise, it must declare its capabilities
honestly, and it must report the artifact files its CLI actually wrote so a role with
declared `outputs:` can complete.

Output: `src/dark_factory/workers/cli_runtime.py`, `src/dark_factory/workers/copilot.py`,
one new `Settings` credential field plus one optional model-pin field, a real registry
registration, a reusable fake-`copilot`-on-PATH test helper, and a unit suite that proves
all of the above with no live `copilot` binary and no live Copilot credential.

**Assumption-delta note (no-change decision):** the worker-registry / `CodingWorker`
identity model goes from one real adapter to three this phase, but no generalization is
introduced — `WorkerRegistry` was already an N-entry name-to-factory map in Phase 1 and
already held `"copilot"`/`"hermes"` keys resolving to placeholders. This phase populates
the existing abstraction; it does not promote, rename or add a noun alongside it.

Locked decisions implemented by this plan:
- D-01: Copilot credential boundary — `Settings.copilot_github_token: SecretStr | None = None`,
  categorically distinct from Dark Factory's own `github_token`, absent-only-at-first-use
  typed error, value reaching the subprocess only through `build_worker_env`. (Task 1)
- D-02: no live `copilot` binary exists here, so the adapter is implemented against
  documented invocation patterns and proven against a faked executable on `PATH`,
  never a live binary. (Task 1, Task 2)
- D-03: `NEEDS_INPUT` signal reuse — the marker literal, protocol text and extraction regex
  are extracted to one shared module and imported by both adapters, so the pause contract
  is identical by construction rather than by inspection. (Task 1, Task 2)
</objective>
