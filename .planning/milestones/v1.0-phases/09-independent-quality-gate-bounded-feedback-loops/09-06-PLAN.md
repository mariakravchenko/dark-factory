  <action>
**Route chosen: derive the worktree inside the rebuild hook.** The debug session offers two
acceptable routes. Take the second one — have `_record_and_maybe_rebuild` call `ensure_worktree`
itself and pass its return value — rather than the one-line-per-call-site route of handing the
constructor the already-computed worktree path. Four reasons, in descending weight:

1. **It proves the claim the module actually makes.** The docstring's D-07 claim is that *a fresh
   process reconstructing the run right then, from only what is already committed, resolves the
   identical `RoleContext`*. A fresh process is not handed a directory path; it reads
   `base_branch` and `working_branch` off the run row and derives the worktree from them. Reading
   those two columns off `fresh_state` — the state just loaded inside the fresh session — extends
   the durability proof to cover path resolution itself, not merely the context build. The other
   route would leave the rebuild borrowing a path the test computed out of band, which is exactly
   the one thing a fresh process cannot do.
2. **It removes the defect class instead of relocating it.** The other route makes a parameter
   named `repo_root` hold a worktree path. Both values are `Path`, both are plausible at every
   call site, `mypy --strict` cannot tell them apart, and the name is the only guard rail there
   is. This defect exists because that name lied; the fix should not make it lie again.
3. **It mirrors `_advance_once` line for line**, so the two sequences can be read side by side
   and any future divergence is visible.
4. **It is free and side-effect-free.** `ensure_worktree`'s Path-1 branch returns immediately
   with no git call at all when the target has a `.git` marker, and the runner created that
   worktree at the top of the very `_advance_once` that is currently calling the worker. The
   branch is guaranteed taken.

**`tests/db/test_feedback_reaches_developer.py` — edit `_record_and_maybe_rebuild` only.** Inside
the existing `with self._session_factory() as fresh_session:` block, after `fresh_state` is loaded
and asserted non-`None` and after `role_def` is looked up, bind a local `work_dir` to
`ensure_worktree(self._repo_root, self._run_id, ...)` passing `base_branch=fresh_state.base_branch`
and `working_branch=fresh_state.working_branch` as keywords — the parameters are keyword-only.
Then change the `build_role_context` call's second positional argument from the stored attribute
to that new local. Name the local `work_dir`, matching `_advance_once`'s own local, so the mirror
is obvious to a reader comparing the two.

Read the branch values from `fresh_state`, never from an attribute captured at construction time.
That choice is the whole point of route 2: it is what makes the derivation part of the durability
proof rather than a convenience.

Leave `__init__`, the `repo_root` parameter name, `self._repo_root`, and **both** construction
sites untouched. Under this route `repo_root=root` at those sites is already correct — the
attribute genuinely holds a repo root and is now used as `ensure_worktree`'s repo-root argument,
which is what it was always named for.

Do **not** add a runtime assertion that the derived worktree differs from the stored root.
`worktree_path` is pure path arithmetic on `repo_root.resolve().parent`, so such an assertion
could never fire and would read as a live check while being dead weight. The structural guard
below is the real pin.

**Extend the module docstring.** The existing paragraph describing the rebuild says it proves
D-07's durability guarantee. Add to it that the rebuild now derives the worktree the way a fresh
process does — `ensure_worktree` from the persisted `base_branch` / `working_branch` columns —
and record why: the run tree and the role context resolve against the worktree, never against the
config repo root, which `worktree_path` makes a sibling rather than an ancestor. Cite gaps G-09-6
and G-09-7 and the debug session path so a future reader cannot mistake the derivation for
redundant ceremony and simplify it back into the bug.

**`tests/unit/test_role_context_rebuild_uses_the_worktree.py` — new DB-free guard module.** This
is the half that restores detection. The behavioural proof is db-tier and unrunnable here; this
guard runs in the unit tier on every push, with no database, and fails the moment the rebuild's
context root stops being the `ensure_worktree`-derived value.

Mirror `tests/unit/test_write_scope_guard_covers_bounce.py` exactly: a module docstring stating

`pytestmark = pytest.mark.unit`, a module-level constant resolving the subject file via

function.

Write three helpers: one returning every `ast.Call` in a tree whose callee unparses to a given
name; one locating the `ast.FunctionDef` named `_record_and_maybe_rebuild`; and one returning the
single name assigned by the `ensure_worktree` call inside a given function — raising

Every assertion carries a message explaining the failure in terms of the bug, not the AST — a

directions.
