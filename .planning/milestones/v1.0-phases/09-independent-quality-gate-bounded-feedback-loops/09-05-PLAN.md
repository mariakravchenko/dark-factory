<objective>
Close verification gap CR-02: `run_quality_gate` redacts each command's captured `stdout` and
`stderr` against `known_secrets`, but stores the configured `command` string itself verbatim.
`verification/quality_gate.json` is force-added and committed onto the run's working branch by
`commit_run_artifacts`, so a credential an operator embeds directly in a
`.dark-factory.yaml` `quality_gate.commands` entry — an authenticated health-check `curl -H
"Authorization: Bearer <token>"` is the realistic authoring pattern — is committed to git
history in the clear and cannot be recalled.

Purpose: restore compliance with this project's own hard Security constraint
(`.claude/CLAUDE.md`: infrastructure credentials "must never reach workers, artifacts, prompts,
event payloads, comments, logs, or reports"), which `verification/quality_gate.json` violates
today, and with this phase's own T-09-03 threat-mitigation claim and `09-03-PLAN.md`'s
human-check step 4.

Output: one redaction call at the point of model construction, and a unit-tier proof that
carries the property end to end from a configured command string through the persisted model to
the bytes on disk.

**Scope discipline.** This plan addresses gap CR-02 only. Gap CR-01 is closed by
`09-04-PLAN.md`; the two share no file and run in the same wave. The seven
`behavior_unverified_items` in `09-VERIFICATION.md` are not gaps and generate no task here —
they are recorded under Manual-Only Verification in `09-04-PLAN.md`.

`As a … I want to … so that …` user-story form, so no user story is synthesised (inventing one
is forbidden). This is a gap-closure pass on an already-shipped slice; the applicable

**`src/dark_factory/orchestrator/quality_gate.py` — one changed argument.** In
`run_quality_gate`'s loop, replace the `GateCommandResult(...)` call's `command=command`
argument with `command=str(redact(command, known_secrets=known_secrets))`. This is the exact
form `09-REVIEW.md`'s CR-02 prescribes and is deliberately identical in shape to the two lines
directly above it that already build `stdout` and `stderr` — same function, same keyword, same
`str(...)` coercion (`redact` is typed to return `Any` because it recurses over containers, so
the coercion is what keeps the field's `str` annotation honest under `mypy --strict`).

Keep `patterns` at its default `True`, matching `stdout`/`stderr`. That default is load-bearing
here rather than incidental: the D-15 pattern table includes a dedicated
`Authorization: …Bearer …` rule and the GitHub/postgres token shapes, so a credential embedded
in a gate command is scrubbed even when that particular value was never registered in
`Settings` — defence in depth on top of the exact-value substitution.

Do **not** apply `_cap_output` to the command string. The cap exists because captured output can
be an unbounded pytest traceback; a configured command is a short, operator-authored line, and
truncating it would destroy exactly the identifying information the artifact exists to hand the
Developer.

**Extend `run_quality_gate`'s docstring.** Its current redaction paragraph says each captured
`stdout`/`stderr` is redacted before the cap is applied "so no unredacted copy of a leaked
credential ever exists in the returned model". Widen that paragraph to name all three redacted
fields and to record *why* the command string belongs in the set: `verification/quality_gate.json`
is force-added and committed onto the run's working branch, so unlike a transient log line a
credential in this file is permanent and unrecallable — and a `quality_gate.commands` entry is
the surface an operator is most likely to embed one in by hand. Cite the project's Security
constraint and gap CR-02 so a future reader cannot mistake the call for redundant defensive
noise and remove it.

**`tests/unit/test_quality_gate.py` — two new tests, written before the edit and watched fail.**
Place both immediately after the existing `test_a_known_secret_value_in_stdout_is_redacted` so
the redaction cluster reads together.

*Test A — the model field.* Name it for the property, in the file's existing sentence style:
`test_a_known_secret_value_in_the_configured_command_is_redacted`. Build a genuinely runnable
command whose *literal text* carries the secret — `_py("-c", "pass", secret)` passes it as an
inert extra argv element, so the child exits 0 and the scenario proves redaction rather than a
crash. Call `run_quality_gate` with `known_secrets={secret: "test_secret"}` and assert the secret
is absent from `result.commands[0].command` and that `[redacted:test_secret]` is present.
Use a secret of at least 8 characters — `_scrub_known` deliberately skips shorter values so a
short configured secret cannot turn redaction into a string shredder, and a 7-character fixture
would produce a silently vacuous test.

*Test B — the written bytes.* Name it
`test_a_known_secret_in_a_command_never_reaches_the_written_artifact`. This is the half that
actually matches the threat: the field being clean is only meaningful because the file is what
gets committed. Run the same gate, then `ensure_run_tree(tmp_path)` and
`write_quality_gate_result(tmp_path, result)` following the existing
`test_write_quality_gate_result_writes_under_verification` idiom, read
`tmp_path / "verification/quality_gate.json"` back as text, and assert the secret does not appear
anywhere in it while `[redacted:test_secret]` does.

Leave every existing test in the module unchanged. In particular
`test_two_passing_commands_yield_pass_with_two_entries_in_order` asserts `.command` equality
against the configured strings and must keep passing — it does, because those strings contain no
known secret and no D-15 pattern match, so `redact` returns them unchanged. If that test does
start failing, the cause is a real over-redaction problem worth surfacing, not a test to relax.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.dark-factory.yaml` `quality_gate.commands` → persisted artifact | operator-authored configuration text is copied verbatim into a model field that is serialised to disk |
| `verification/quality_gate.json` → git history | `commit_run_artifacts` force-adds and commits this file onto the run's working branch, making its contents permanent and eventually PR-visible |
| persisted artifact → the Developer's next `RoleContext` | `read_artifact_text` returns this file's contents into a later role's prompt, so anything in it also crosses the orchestrator→worker credential boundary |
