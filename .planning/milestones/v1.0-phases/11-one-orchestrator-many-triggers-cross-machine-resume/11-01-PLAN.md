the deployer docs) expands outward from this slice.

that this is "a new, real production code path." The only stubbing anywhere is the test double.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Dark Factory -> GitHub Actions API | A new outbound call carrying a run id, authenticated with a new credential. The request's inputs become publicly visible (to anyone with repository read access) in the dispatched run's Actions UI and job logs. |
| Dark Factory -> worker subprocess | The existing credential boundary. `dispatch_github_token` joins `database_url`, `github_token` and `github_webhook_secret` as an infrastructure credential that must never appear in a worker's environment, prompt, artifact, event payload or log. |
| GitHub API error response -> Dark Factory error message | A GitHub error response can echo request headers, including the `Authorization` header carrying the dispatch token. |
| GitHub (inbound webhook) -> Dark Factory | Unchanged from Phase 10 — HMAC verification via `githubkit.webhooks.verify` runs before anything else and is untouched by this plan. |
