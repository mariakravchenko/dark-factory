<objective>
Wave 4 — expansion out from the proven tracer. Three widenings on top of the config-driven run 03-03 established:

1. **Before/after hooks fire (CFG-04 runtime).** `_run_current_role` resolves the current role's dict from the snapshot and invokes its `before` action names through the `ActionRegistry` immediately before the worker call and its `after` names immediately after — outside the transaction, with no role-name branch. The five built-ins are no-ops, so the observable effect is "the named callables ran, in order"; a test-registered action proves a new action is usable from config with zero orchestrator change.
2. **Role YAML drives behaviour (CFG-02 / CFG-03, SC2).** Editing `.dark-factory/roles/BA.yaml` — its `worker`, its `before` / `after`, its `instructions` path — changes what a fresh run executes with no Python change, and the instruction Markdown is inlined verbatim into `runs.workflow`. Plus a snapshot round-trip proof (CFG-05).
3. **Snapshot survives an edit during a pause (CFG-05, SC3).** Pause a run on a `NEEDS_INPUT` script, rewrite `.dark-factory.yaml`, `resume --answer`, and the run executes the creation-snapshot role order, not the edited file — with `resume` / `drive` calling `load_effective_config` zero times.

Then the phase acceptance gate (sibling of `test_phase2_acceptance.py`) and the `COVERAGE.md` no-external-API declaration.
