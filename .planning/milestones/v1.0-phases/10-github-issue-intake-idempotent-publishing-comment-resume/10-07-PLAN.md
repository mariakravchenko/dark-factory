<objective>
Close G-10-1's two serial root causes and the masked-assertion risk the same diagnosis
surfaced.

Four real-CLI-subprocess integration tests copy this repository's shipped
`.dark-factory.yaml` verbatim into a throwaway git repo that cannot satisfy its two
repo-specific declarations: `quality_gate.commands` names this repo's own `uv run pytest`
(exit 5, `EXIT_NOTESTSCOLLECTED`, in a repo with no Python project), and
`publishing.create_pr: true` has no `repository.github_owner`/`github_repo` behind it.
The first makes the gate FAIL forever and bounces QA -> DEVELOPMENT until
`quality_gate_max_iterations` is exhausted; the second is latent and fails the run the
instant the first is fixed. `tests/conftest.py`'s `_write_config_tree` already neutralizes
both for ~24 db-tier tests -- these four modules were never covered by that mitigation
because they copy the shipped file directly.

`src/dark_factory/orchestrator/runner.py` is CORRECT and is not touched by this plan.
The gate invocation, the publish branch and the bounce logic were all confirmed correct
during diagnosis. The entire defect is in the test harness.

Purpose: restore the only four tests in the suite that prove the SHIPPED configuration
drives a real `dark-factory run` subprocess to `COMPLETED` -- the end-to-end evidence
behind GIT-03 -- and make the three sibling negative controls fail for their own stated
reason rather than for gate exhaustion.

Output: one shared, unit-proven `tests/support/shipped_config.py` harness that every
integration module uses (removing the duplication that let this drift for two phases),
a DB-free guard proving the neutralization removes exactly two keys and nothing else,
and three strengthened negative-control assertions.
</objective>
